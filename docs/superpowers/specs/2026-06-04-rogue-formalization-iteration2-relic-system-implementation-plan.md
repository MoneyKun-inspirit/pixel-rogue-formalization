# 迭代 2 实现计划：遗物系统首版

## 1. 目标
基于已确认的遗物系统规格，在当前 Demo 中落地“固定阶段触发 + 独立遗物面板 + 少量高影响遗物”的首版实现。

本轮实现目标不是扩充大量内容，而是优先打通以下闭环：
- 中局固定节点弹出遗物三选一
- 选择遗物后，运行时状态、HUD 和战场反馈同步变化
- 同一职业在拿到不同遗物后出现明显打法偏转

## 2. 实现范围
### 2.1 本轮实现
- 新增遗物类型、状态和运行时字段
- 在内容配置中加入首版 6 件遗物
- 在主循环中加入遗物节点触发、阻断和应用逻辑
- 新增遗物面板 UI
- 在 HUD 中增加遗物摘要
- 为至少 2 件遗物加上明确可视化反馈
- 补充遗物相关自动化测试

### 2.2 本轮暂不实现
- 精英怪掉落遗物
- 地图拾取式遗物
- 遗物叠层
- 遗物权重评分器
- 完整元素反应逻辑

## 3. 实施顺序
### 阶段 1：补齐类型与配置
目标：建立遗物的最小可用数据骨架。

改动：
- `src/game/types.ts`
  - 新增 `RelicCategory`
  - 新增 `RelicDefinition`
  - 新增 `OwnedRelic`
  - 给 `RunMode` 增加遗物选择状态
  - 在 `RunState` 中加入遗物数组、待选遗物、下一次遗物时间、已触发次数
  - 在 `BuildState` 中加入统一遗物结算字段
- `src/game/content.ts`
  - 新增 `relicPool`
  - 写入首版 6 件遗物配置
  - 为需要承接条件的遗物增加轻量过滤标签

完成标准：
- 类型层能表达遗物配置、持有状态和待选状态
- 运行时创建初始局时已带上默认遗物字段

### 阶段 2：打通引擎运行时
目标：让遗物节点能在正确时间稳定触发，并阻断战斗推进。

改动：
- `src/game/engine.ts`
  - 新增 `buildRelicOptions(run)`
  - 新增 `shouldTriggerRelicChoice(run)`
  - 新增 `applyRelic(run, relic)`
  - 在 `createInitialRun()` 中写入初始遗物状态
  - 在 `updateRunState()` 中插入遗物触发时机检查
  - 当遗物面板打开时暂停战斗推进，但保留已存在的面板覆盖行为

实现重点：
- 避免遗物与升级面板同时出现
- 避免在胜利/失败态继续触发遗物
- 首版候选生成只做轻量倾向，不做复杂权重系统

完成标准：
- 运行 80 秒左右必定进入第一次遗物选择
- 选择后战斗继续，第二次节点仍能按时触发

### 阶段 3：接入页面与 HUD
目标：让玩家能明确感知自己正在做“遗物抉择”，并在选择后看到构筑摘要。

改动：
- 新增 `src/components/run/RelicPanel.tsx`
  - 复用升级卡片样式语言，但标题和标签明显区别
  - 支持鼠标与 `1 / 2 / 3` 选择
- `src/pages/RunPage.tsx`
  - 同时处理升级快捷键和遗物快捷键
  - 根据模式显示 `UpgradePanel` 或 `RelicPanel`
- `src/components/run/RunHud.tsx`
  - 新增“本局遗物”摘要区
  - 最多显示 2-3 条关键遗物效果
- `src/components/run/useRunSimulation.ts`
  - 补充遗物快照克隆
  - 新增遗物选择入口

完成标准：
- 页面中可正常弹出遗物面板并完成选择
- HUD 能稳定显示已选遗物摘要

### 阶段 4：接入战斗表现
目标：保证遗物不是只有逻辑，没有像素反馈。

优先接入可见反馈的遗物：
- `裂轨羽冠`
  - 表现为副弹道或命中后裂轨分叉
- `熔炉徽记`
  - 表现为贴身 aura、近身圈层或玩家外环强化
- `偏元素容器`
  - 表现为主元素颜色强化、拖尾或命中特效增强

可先用统一状态字段驱动：
- 投射物分裂数
- 近身增益激活状态
- 元素聚焦类型

改动：
- `src/game/engine.ts`
  - 把遗物效果写入现有伤害、投射物和区域逻辑
- `src/components/run/CanvasArena.tsx`
  - 为关键遗物增加最小必要的像素视觉反馈

完成标准：
- 至少 2 件遗物在战场上能被肉眼快速分辨

### 阶段 5：补测试与回归验证
目标：为遗物系统建立最小可靠保护网。

改动：
- `src/game/engine.test.ts`
  - 测试指定时间点会触发遗物选择
  - 测试遗物选择期间战斗暂停
  - 测试遗物不会重复出现
  - 测试至少 2 件遗物会改变战斗行为
- 运行：
  - `npm run check`
  - `npm run lint`
  - `npm test`
  - `npm run build`
- 手动试玩：
  - 抽查游侠或战士两条遗物路线
  - 确认遗物面板和升级面板不冲突

完成标准：
- 检查、测试和构建全部通过
- 实机验证能看出中局遗物分流

## 4. 关键实现决策
### 4.1 模式层
建议把 `RunMode` 从当前的：
- `running`
- `levelup`
- `defeat`
- `victory`

扩展为增加：
- `relic-choice`

原因：
- 比额外挂一个布尔标记更清楚
- 页面和主循环都更容易判断当前阻断类型

### 4.2 面板复用策略
不把 `UpgradePanel` 硬改成超大通用面板。

策略：
- 保留 `UpgradePanel.tsx`
- 新建 `RelicPanel.tsx`
- 如有重复，再抽共享卡片样式

原因：
- 升级和遗物在文案语义、视觉层级和未来扩展上都是两个系统
- 分开组件更容易控复杂度

### 4.3 遗物效果落点
首版尽量把遗物结算收束到 `BuildState` 和少量直接状态修改，不做大面积散装判断。

例如：
- 主动技能增伤和击杀返还走技能节奏字段
- 投射物裂轨走投射物附加行为字段
- 贴身增伤走距离判断 + 统一增益字段
- 元素聚焦走元素辅助字段

## 5. 风险控制
- 如果单次实现面过大，优先保证：
  - 遗物触发链路
  - 遗物面板
  - HUD 摘要
  - 2 件高反馈遗物
- 若某些遗物联动过深，可先降级为统一字段实现，后续再细化
- 若 `CanvasArena.tsx` 反馈过多，优先保留最能表达构筑差异的两类视觉

## 6. 验收清单
- 遗物节点会在固定时间正常出现
- 遗物选择时战斗暂停
- 遗物面板与升级面板互不冲突
- HUD 能正确显示遗物摘要
- 至少 2 件遗物有明确战场反馈
- 自动化测试、类型检查、lint 和 build 全部通过
